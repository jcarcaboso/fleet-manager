# Fleet Manager 0.8.1

This patch release preserves Codex context and automatic-compaction limits from
CLIProxy model discovery through the Server, Agent cache, and generated Codex
catalog. Previously, Fleet discarded these limits, which could leave long
conversations without their normal compaction safeguards.

## Codex context limits

Fleet now carries each model's optional `context_window`, `max_context_window`,
and `auto_compact_token_limit`. The default context window remains separate from
the larger maximum override window. Explicit compaction thresholds are
preserved; a null threshold lets Codex derive its own value from the context
window.

Malformed limits fail the refresh without replacing the last valid catalog.
Legacy catalogs and Agent caches remain readable. Fleet does not invent missing
limits, apply metadata from another endpoint, or overwrite local
`model_context_window` and `model_auto_compact_token_limit` settings.

## Upgrade

Upgrade proxy-assigned `fleet-agent` installations to 0.8.1 before the Server,
or upgrade both together. Older Agents reject the added catalog fields and
retain their previous catalog.

For a requested deployment after publication, set
`FLEET_IMAGE=skorcius/fleet-manager:0.8.1` in the installation's `.env`, then run
`docker compose pull` and `docker compose up -d --force-recreate --wait`.
Preserve existing configuration, certificates, credentials, Docker volumes,
and Agent state. No re-enrollment or database migration is required.

Refresh models in the dashboard, wait for successful Node reconciliation, and
restart existing Codex sessions to load the corrected catalog. Existing Agent
caches gain context limits only after a successful refresh from the updated
Server.

This update restores advertised context safeguards. It does not guarantee
recovery of an already oversized conversation or fix every stream disconnect.
After reloading the limits, try native `/compact`. If compaction fails, preserve
the original conversation and start a fresh thread with a short handoff.

See the [CLIProxyAPI operations guide](../technical-design/cliproxy-operations.md).

## Verification

Regression tests cover Server discovery and selected catalog delivery, nullable
and malformed limits, Agent cache round trips and refresh, endpoint isolation,
legacy caches, and native restoration without changing local overrides.

Local verification passed 130 Server tests and 76 Rust tests, formatting, the
Release build, Clippy, documentation links, and a fresh RustSec dependency audit.
The Server suite ran serially to avoid local rootless Docker port collisions.
