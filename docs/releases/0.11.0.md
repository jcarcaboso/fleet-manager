# Fleet Manager 0.11.0

This minor release replaces the dashboard's Operator-token sign-in with
**dashboard accounts**, adds **themes** with dark as the default, and makes the
Agent **repair Fleet-owned AI-client settings** that something outside Fleet
changed, reporting repairs it cannot make to the Server. Dashboard sign-in
changes for every installation: read [Breaking changes](#breaking-changes) and
[Upgrade](#upgrade) before deploying.

Operator tokens, the `fleet` CLI and `/operator/v1` work as in 0.10.0. The
release has two database migrations.

## Dashboard accounts

- **Name and password.** The dashboard signs in with an account instead of an
  Operator token. Operator tokens remain the credential of the `fleet` CLI and
  of `/operator/v1` only.
- **Default account.** While an installation has no account, the first sign-in
  creates `fleet` with the password `fleet` and the `admin` scope. It must choose
  a new password (10 to 256 characters) before any other page opens. Until it
  does, anyone who reaches the dashboard can claim it, so change it right after
  installing or upgrading.
- **Accounts page.** Admins add accounts with the `read`, `operate` or `admin`
  scope, change scopes, set a temporary password and delete accounts. A new
  account, and one whose password an admin set, chooses its own password at the
  next sign-in. The last admin and the signed-in account cannot be removed.
- **Your account.** Every account changes its own password and picks the theme
  on the new **Your account** page, opened from the name in the top bar.
- **Sessions.** Changing an account's password or scope, or deleting it, ends its
  open sessions. A user's own password change keeps the session that made it.
- **Passwords** are stored as PBKDF2-SHA256 hashes (600,000 iterations, random
  salt) and never leave the Server. An unknown name takes as long to refuse as a
  wrong password, and sign-in keeps the per-address limit of 20 per minute.
- **Audit.** Sign-ins (`account.signed_in`, `account.sign_in_failed`) and every
  account change are audited. Audit items gain `account`, the account an event
  is about, and `detail` (the scope, or `read -> operate` for a scope change).
  The Audit page shows them in its **Subject** column. Passwords are never
  recorded.

## Themes

- Dark is the default. Light and System (follows the operating system) are on
  the sign-in page and on **Your account**.
- The choice is kept in this browser (`fleet-theme`, the only thing the
  dashboard stores) and applied before the page first draws, so a Light choice
  does not flash dark.
- Status badges with white text meet a 4.5:1 contrast in both themes.

## Agent repairs and repair failures

- **AI-client settings are repaired.** When something outside Fleet changes,
  removes or deletes Fleet-owned settings in a Codex, OpenCode or Claude
  configuration, the Agent writes them again on its next idle cycle, keeps the
  user's original values from its receipt, and reports the change as drift.
- **One failure no longer blocks the rest.** The idle cycle applies every active
  Assignment even when one fails, and logs each failure as
  `could not repair <target>: …`.
- **Repair failures reach the Server.** The Agent sends them with the new
  `PUT /agent/v1/repair-failures`, and the Server shows each one as a
  `repair_failed` problem until the repair succeeds.
- **Service logs.** The launchd job of `fleet-agent service install` logs to
  `<state-dir>/logs/agent.log` (started again past 10 MiB), and the Homebrew
  service to `$(brew --prefix)/var/log/fleet-agent.log`. `fleet-agent service`
  refuses to manage a Homebrew-installed service and names the `brew services`
  command to use instead.

## Breaking changes

- **Dashboard sign-in uses accounts.** The Operator token no longer signs in to
  the dashboard. `POST /dashboard/api/login` takes `{ "name", "password" }`; the
  old `{ "token" }` body is refused with `400 invalid_request`. After the upgrade,
  sign in as `fleet` / `fleet` and choose a new password.
- **Every dashboard route waits for a required password change.** A session
  that must change its password gets `403 password_change_required` from every
  route except `session`, `logout` and `account/password`.
- **Account names** are 1 to 64 characters of `a-z`, `0-9`, `.`, `_` and `-`,
  starting with a letter or digit.
- **Audit items gain `account` and `detail`.** Clients that reject unknown
  members must accept them (`null` for events that are not about an account).
- **Smoke scripts.** `scripts/smoke-dashboard.py` signs in with
  `FLEET_DASHBOARD_NAME` and `FLEET_DASHBOARD_PASSWORD` (default `fleet` /
  `fleet`). `scripts/smoke-enrollment.py` needs both and an operate or admin
  account whose password has already been changed.
- **`fleet-agent service` and Homebrew.** On a machine whose Agent runs as a
  Homebrew service, `fleet-agent service` actions stop with an error that names
  the `brew services` command; `install`, `start` and `restart` also refuse while
  both kinds of service are installed.

## Upgrade

Upgrade the Server and the dashboard together. Agents can be upgraded before or
after the Server: a 0.11.0 Agent ignores the `404` of an older Server for repair
failures, and an older Agent never sends them.

1. Back up PostgreSQL and the private configuration as described in the
   [backup guide](../technical-design/backup-restore.md).
2. Set both images in `.env`:
   `FLEET_IMAGE=skorcius/fleet-manager:0.11.0` and
   `FLEET_DASHBOARD_IMAGE=skorcius/fleet-manager:dashboard-0.11.0`.
   `setup.py --add-dashboard` wrote the 0.10.0 dashboard image into `.env`, so
   change that line too. `compose.yaml` is unchanged from 0.10.0.
3. Run `docker compose pull` and `docker compose up -d --force-recreate --wait`.
   The migrations `AddNodeRepairFailures` and `AddOperatorAccounts` run before
   the Server starts. They create two small tables and add two nullable columns
   to `audit_events`; none rewrites existing rows.
4. Open the dashboard right away, sign in as `fleet` with the password `fleet`
   and choose a new password. Then add an account for each person on the
   **Accounts** page.
5. Upgrade Agents as usual. On macOS, run `fleet-agent service install` again
   after upgrading a `fleet-agent service` installation to add the log paths to
   its launchd job. For Homebrew, run `brew upgrade fleet-agent` and
   `brew services restart fleet-agent`.

After a partial upgrade, a 0.10.0 dashboard against a 0.11.0 Server cannot sign
in (it still sends a token), and a 0.11.0 dashboard against a 0.10.0 Server is
refused at sign-in. Upgrade both images together.

## Security notes

- Until the default password is changed, anyone who can reach the dashboard can
  claim the `fleet` admin account, including right after an upgrade from 0.10.0.
  This is accepted for self-hosted installations; change it before the dashboard
  is reachable by others.
- An admin request that was already waiting while its account was demoted,
  deleted or given a new password cannot act: the Server checks the account again
  under the account lock.
- The sign-in rate limit is per address, not per account.
