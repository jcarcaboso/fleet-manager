# Fleet Manager 0.6.1

This release modularizes the clients and Server without changing configuration
schemas, API routes, authentication, receipts, journals, or database transactions.
The Server image, `fleet`, and `fleet-agent` all use version `0.6.1`.

## Changes

- Separate Operator command parsing and dispatch from HTTP transport.
- Register Codex and OpenCode adapters explicitly, with client-specific
  rendering and restoration in separate modules.
- Extract Server service registrations, middleware, and route composition.
- Extract the ordered source target publishers from Git scanning.
- Add [client](../plans/client-modularity.md) and
  [Server](../plans/server-modularity.md) plans and an
  [extension guide](../technical-design/extending-fleet.md).

These are compiled modules, not runtime plugins. No new dependencies or
database migrations are included.

## Upgrade

Back up PostgreSQL and private configuration, then set
`FLEET_IMAGE=skorcius/fleet-manager:0.6.1` in the deployment's `.env` and run
`docker compose pull` followed by `docker compose up -d --force-recreate --wait`.
Keep existing volumes, secrets, and Node state. Do not rerun initial setup.

Update both Homebrew clients with `brew update` and
`brew upgrade jcarcaboso/fleet/fleet jcarcaboso/fleet/fleet-agent`.
Restart the Agent service after updating. Existing Nodes do not need enrollment
again, and existing `fleet/v1` and `fleet/v2` manifests remain valid.

## Verification

The refactor passed 92 Server tests, 62 Rust workspace tests, Linux and macOS CI,
formatting and lint checks, the dependency audit, and isolated HTTPS smoke tests
with the refactored CLI and Server. The smoke tests cover enrollment, exact retry,
mTLS, alias changes, renewal, credential isolation, and revocation.
