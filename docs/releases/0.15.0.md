# Fleet Manager 0.15.0

The Models page now controls which AI clients get each group of CLIProxy
models. Changes apply per proxy. Use client checkboxes or **Publish to all**.
Model and family selection still controls which models within each group are
included. The Server rejects changes that would remove a model pinned to a
client in `fleet.yml`.

This release also adds Linux ARM64 archives and Homebrew support for `fleet`
and `fleet-agent`. The Server and dashboard container images remain Linux amd64.

## Breaking changes

Updated Agents build each client's proxy configuration using these defaults:

| Model group | Default clients |
|---|---|
| `claude-` | Claude Code only |
| `gpt-` | Codex and OpenCode |
| All other model IDs | OpenCode only |

If a proxy was configured to share Claude models, that choice is preserved.
This controls Fleet's generated configuration, not proxy authorization.

## Upgrade

1. Back up the Server database. The
   [backup guide](../technical-design/backup-restore.md) shows how to use
   `python3 scripts/postgres-backup.py backup --container fleet-postgres-1 .local/backups/before-0.15.0`.
2. Once the release is published, upgrade the Server and dashboard together.
   Set `FLEET_IMAGE=skorcius/fleet-manager:0.15.0` and
   `FLEET_DASHBOARD_IMAGE=skorcius/fleet-manager:dashboard-0.15.0` in `.env`
   before pulling both images. There is no database migration or reenrollment.
3. Before updating Agents, check `fleet.yml` for pinned models that would fall
   outside their client's default route. Set an explicit route on the Models page
   or change the pin. Older Agents still use the legacy catalog behavior; the
   new routing takes effect after the Agents update.

See [CLIProxy operations](../technical-design/cliproxy-operations.md) for
Claude Code picker support, offline behavior, and routing details.

## Verification

The 0.14.0 and 0.15.0 Agents both enrolled and polled against the candidate
Server on Linux. Disposable stacks also passed the CLIProxy, dashboard, and
Agent self-update and crash-loop rollback checks. Published release signing,
Homebrew installation, and macOS service behavior were not verified locally.
