# Fleet Manager 0.15.1

Images: `skorcius/fleet-manager:0.15.1` for the Server and
`skorcius/fleet-manager:dashboard-0.15.1` for the dashboard, Linux amd64.

This release fixes the Claude Code `/model` picker that 0.15.0 Agents write for
CLIProxy routes. There is no database migration, dependency update, or change to
enrollment, ownership receipts, or service definitions.

## Claude Code model picker

The 0.15.0 Agent wrote each `modelPicker` row in `~/.claude/settings.json` as
`{ "value": "<model>" }`. Claude Code expects `{ "model": "<model>" }`, so it
ignored every routed model and showed a settings warning on startup:

```
modelPicker.options.0: modelPicker row "model" Invalid input: expected string, received undefined. This row was ignored; the other rows still apply.
```

The 0.15.1 Agent writes the `model` key. It rewrites the old rows the next time
it successfully reconciles the Node's Claude Code target, and a drift report for
that target may appear. The report is expected and needs no action.

## Upgrade

1. Once the release is published, upgrade the Server and dashboard together.
   Set `FLEET_IMAGE=skorcius/fleet-manager:0.15.1` and
   `FLEET_DASHBOARD_IMAGE=skorcius/fleet-manager:dashboard-0.15.1` in `.env`,
   then run `docker compose pull` and `docker compose up -d --force-recreate --wait`.
   The Server mirrors only the Agent release of its own version, so upgrade it
   before updating Agents.
2. Update Agents from the dashboard, or with `fleet nodes update <node>` or
   `fleet nodes update --all-outdated`. After the Agent repairs the settings,
   restart any open Claude Code sessions to load the corrected picker.

## Verification

- Agent tests cover the picker rows Fleet writes, their restoration in native
  mode, and the per-client model routes.
- With Claude Code 2.1.330 and an isolated configuration directory, `value`
  rows produced the settings warning and `model` rows started without it.
- CI must pass on the PR before merge and on the release commit before tagging.
  Image publication, release tagging, signed archives, Homebrew updates, and
  verification of published artifacts happen after the release PR is merged.
  macOS behavior is not verified locally.
