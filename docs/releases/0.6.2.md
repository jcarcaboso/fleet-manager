# Fleet Manager 0.6.2

CLIProxy model discovery now runs on the Server. Nodes opt in with
`mode: cliproxy` and receive the available models and advertised reasoning
efforts automatically. A `model` entry is an optional default override.
The Server image, `fleet`, and `fleet-agent` use version `0.6.2`.

## Changes

- Discover and cache CLIProxy models on the Server, refreshing on demand at
  most once per minute.
- Serve the catalog over mTLS only to Nodes with a current proxy Assignment.
- Render advertised effort choices for Codex and model variants for OpenCode.
- Keep an available local model selection when no default is configured;
  otherwise select the first advertised model.
- Retain the last valid catalog for the same endpoint during discovery failures.

Older proxies that return only model IDs remain supported. Fleet does not
invent effort choices when the proxy omits them. Catalog changes reach Nodes
through normal reconciliation without YAML changes.

## Upgrade

Set `FLEET_IMAGE=skorcius/fleet-manager:0.6.2` in the deployment's `.env`, then
run `docker compose pull` and `docker compose up -d --force-recreate --wait`.
Preserve existing volumes, secrets, and Node state.

Update the clients with `brew update` and
`brew upgrade jcarcaboso/fleet/fleet jcarcaboso/fleet/fleet-agent`, or install
the release archives. Restart the Agent service after updating.

Upgrade the Server and selected Agents before removing `model` from live YAML.
Existing explicit model defaults remain supported. No database migration or
Node re-enrollment is required.

See the [CLIProxy operations guide](../technical-design/cliproxy-operations.md)
and [manifest example](../../examples/source/fleet-cliproxy.yml).
