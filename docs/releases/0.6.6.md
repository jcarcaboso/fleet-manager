# Fleet Manager 0.6.6

This release fixes automatic certificate renewal for Nodes that stay offline
past their certificate expiration. The Agent now renews before resuming normal
requests, using its existing private key to authenticate the renewal.

Only the renewal endpoint accepts expired Node certificates. Explicitly revoked
Nodes and credentials remain blocked, and the issuing CA must still be valid.
The Server does not revoke credentials merely because a Node is offline.

## Upgrade

Set `FLEET_IMAGE=skorcius/fleet-manager:0.6.6` in the deployment's `.env`, then
run `docker compose pull` and `docker compose up -d --force-recreate --wait`.
Upgrade `fleet-agent` to 0.6.6 on affected Nodes and restart their services.
Both the Server and Agent need this update for automatic expiration recovery.
Preserve the existing Node state, private key, and issuing CA. No re-enrollment
is needed for an expired, non-revoked credential. Explicit revocation and lost
private keys still require Operator-authorized recovery.

## Verification

Regression tests cover renewal after 60 days offline, normal-endpoint rejection
of expired certificates, Node and credential revocation, and rejection of
future-valid certificates, unrelated issuers, and expired issuing CAs.

Local verification passed 113 Server tests and 66 Rust tests, formatting,
Clippy, and documentation-link checks. The amd64 Docker image passed disposable
Compose startup, migrations, and the HTTPS smoke test. A real 0.6.6 Agent also
recovered from a CA-signed expired certificate over mTLS, rotated its key,
preserved its Node identity, and resumed polling. The same test confirmed that
normal endpoints and renewal after explicit revocation rejected the old credential.
