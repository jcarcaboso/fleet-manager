# Fleet Manager 0.6.0

This prepared release adds versioned `fleet/v2` manifests and per-Node
CLIProxyAPI connections for Codex and OpenCode. Fleet discovers the proxy model
list on each Node, keeps the last valid catalog through transient outages, and
updates only the client configuration fields it owns. Selecting `native`
restores those fields without changing either client's OAuth credentials.

The shared proxy key is not part of `fleet.yml`, an Assignment, a Bundle, or
PostgreSQL. The Server reads it from an owner-only mounted file and authorizes
delivery only to Nodes with a current proxy Assignment. The Agent stores its
copy in private state and configures both clients to read that file instead of
embedding the value in TOML or JSONC.

## Upgrade

Upgrade `fleet-agent` on every selected Node before publishing `fleet/v2`
AI-client Assignments. Older Agents reject the new typed Assignment. Existing
`fleet/v1` repositories remain supported and require no changes.

Apply the included database migration, materialize the proxy key outside Git,
and start the homelab stack with both Compose files. Then publish the `fleet/v2`
manifest. See the [CLIProxyAPI operations guide](../technical-design/cliproxy-operations.md)
for setup, rotation, rollback, and release checks.

## Compatibility

The release gate pins Codex `0.154.0` and OpenCode `1.18.31` for container
checks. The Codex check loads the same generated catalog shape used by the
Agent; both checks require a live shell-tool round trip. The implementation uses
documented OpenAI-compatible HTTP behavior and a clean implementation of the
public client configuration formats. It does not copy EasyCLIProxyAPI source or
model templates. EasyCLIProxyAPI and CLIProxyAPI were reviewed as MIT-licensed
interoperability references; their pinned source revisions remain recorded in
the repository research notes.
