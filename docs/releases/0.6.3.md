# Fleet Manager 0.6.3

CLIProxy catalogs now refresh independently of repository changes. The dashboard
shows actionable configuration and sync issues, including a missing CLIProxy key.
The Server image, `fleet`, and `fleet-agent` use version `0.6.3`.

## Changes

- Refresh models for configured Nodes weekly by default. Configure the interval
  with `Fleet:CliProxySyncIntervalSeconds` (10–2592000 seconds), or
  `FLEET_CLIPROXY_SYNC_INTERVAL_SECONDS` in the homelab deployment.
- Serve cached catalogs to Agents and retain the last valid catalog during
  upstream failures. Operators can inspect discovery status and refresh manually.
- Retry failed current AI client Assignments after 60 seconds without requiring
  a repository change, while preserving previous failed attempts.
- Update an existing OpenCode `opencode.jsonc` in preference to `opencode.json`,
  preserving comments and settings Fleet does not own.
- Show missing credentials, catalog failures, repository problems, stale Nodes,
  and failed current Assignments in the dashboard's Issues to resolve section.
  Diagnostics do not expose credentials or raw upstream errors.

## Upgrade

Set `FLEET_IMAGE=skorcius/fleet-manager:0.6.3` in the deployment's `.env`, then
run `docker compose pull` and `docker compose up -d --force-recreate --wait`.
Preserve existing volumes, secrets, and Node state.

Update the clients with `brew update` and
`brew upgrade jcarcaboso/fleet/fleet jcarcaboso/fleet/fleet-agent`, or install
the release archives. Restart the Agent service after updating.

Upgrade both the Server and Agents for retry and OpenCode configuration fixes.
Configure `Fleet.CliProxyApiKey` with a key accepted by CLIProxy when enabling
proxy-backed models. No database migration or Node re-enrollment is required.

See the [CLIProxy operations guide](../technical-design/cliproxy-operations.md)
and [manifest example](../../examples/source/fleet-cliproxy.yml).

## Verification

The change passed 102 Server tests and 65 Rust workspace tests. An isolated
Docker test with a real Agent and a TLS CLIProxy fixture verified scheduled
catalog refresh, recovery without a Git revision change, manual refresh,
Codex and OpenCode configuration updates, cached catalogs during outages,
and restoration of native configuration. Dashboard diagnostics were checked
in Chromium at desktop and mobile sizes. No live inference test was performed.
