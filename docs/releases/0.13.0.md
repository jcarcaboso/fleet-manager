# Fleet Manager 0.13.0

Images: `skorcius/fleet-manager:0.13.0` for the Server and
`skorcius/fleet-manager:dashboard-0.13.0` for the dashboard, Linux amd64.

This release fixes missing Claude Skills after a Server upgrade. Previously,
the Server skipped a source commit that it had already published, even when
the new Server resolved additional Targets. Updating an Agent or rescanning
that same commit could not create the missing `skills/claude` Assignment.

The Server now records a publication version alongside the source commit.
Its startup scan can publish the same commit with the new target resolution.
Only changed or missing Targets receive Assignments. Existing pending or
succeeded Assignments stay intact, and repeated scans create no extra work.
No source commit or Agent-state reset is needed.

The default Claude destination remains `~/.claude/skills`. `excludeClaude`
still controls delivery, and Agents preserve unowned Skills.

## Breaking changes

This fix uses a minor version because it adds the database migration
`20261105120000_VersionSourcePublications`.

The migration marks existing desired revisions as publication version 1 and
changes their unique key to include the publication version. The new Server
publishes version 2. Source commit IDs and historical desired revisions are
preserved.

The migration runs transactionally before the Server starts. It locks
`desired_revisions` while adding the column and replacing its unique index;
the index is not built concurrently. Allow a maintenance window for a large
revision history.

After the same commit has been republished, an older Server cannot safely use
this database because it expects at most one desired revision per source
commit. Do not downgrade only the Server image. To roll back, restore the
pre-upgrade database backup and its matching Server and private configuration.

## Upgrade

1. Back up PostgreSQL and private configuration using the
   [backup guide](../technical-design/backup-restore.md). From a repository
   checkout with access to the installation's Docker daemon:

   ```sh
   python3 scripts/postgres-backup.py backup \
     --container <postgres-container> .local/backups/pre-0.13.0
   ```

2. Preserve `.env`, `secrets/`, `operator.env`, `ssh/`, Agent state, and Docker
   volumes. Upgrade the Server and dashboard together, before updating Agents:

   ```sh
   # Set these image references in the existing deployment's .env:
   # FLEET_IMAGE=skorcius/fleet-manager:0.13.0
   # FLEET_DASHBOARD_IMAGE=skorcius/fleet-manager:dashboard-0.13.0
   docker compose pull
   docker compose up -d --force-recreate --wait
   ```

3. The startup source scan now creates missing Claude Skills Assignments from
   the current source commit. `fleet source rescan` can also request a scan.
   Do not make an empty source commit or delete receipts to trigger delivery.
   Check `excludeClaude` before upgrading Nodes that should not receive
   Fleet-managed Claude Skills.
4. Agents on 0.12.2 or 0.12.3 already support `claude-skills` and can apply these
   Assignments without an Agent upgrade. Older Agents continue receiving their
   supported Targets, but Claude delivery remains pending until they announce
   that capability. After the signed release archives are published, update
   Agents through the dashboard or `fleet nodes update`.
5. Check rollout status and the Node's `~/.claude/skills` destination. No CA
   renewal, reenrollment, or service-definition change is required.

## Verification

- Upgrade regressions cover an existing database, an unchanged source commit,
  missing and already-published Claude Targets, pending and succeeded shared
  Targets, and repeat-scan idempotency.
- Dependencies and release signing keys are unchanged from 0.12.3.
- Local macOS tests encountered four locale-sensitive assertions that pass
  under `en_US`, and a directory-collision fixture that requires a
  case-sensitive filesystem. Linux CI must pass before merge and tagging.
- Native macOS installation and login-startup behavior are not verified by the
  local Server tests.
- Image smoke tests, published archive provenance, manifest signature,
  Homebrew formulas, and a disposable-stack self-update are checked separately
  during publication. Any unfinished checks are reported with the release.
