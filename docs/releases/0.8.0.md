# Fleet Manager 0.8.0

This minor release adds a dashboard option to skip Claude models when configuring
other AI clients. It also includes the
[Claude Code connection support introduced in 0.7.0](0.7.0.md).

## Claude model restriction

In **CLIProxy models → Model selection**, each proxy endpoint has a
**Skip Claude models for other clients** checkbox. It is checked by default,
including for existing selections that do not yet contain this setting.

When checked, Agents exclude model identifiers with a case-insensitive
`claude-` prefix from Codex and OpenCode catalogs before choosing a default.
Claude Code keeps access to the selected Workspace catalog. Uncheck the box and
click **Save selection** to allow Claude models in every client.

The Server stores the choice with the endpoint's existing model-selection
policy. Agents receive it on their next poll and retain it in their model cache
for offline use. Save, reload, reset, and stale-write handling follow the
existing selection controls.

Enabling the restriction is rejected when a current Codex or OpenCode
Assignment pins a Claude model. Change that Assignment's default or leave the
checkbox unchecked. If filtering leaves no usable models, Agent reconciliation
fails without changing the existing client configuration or ownership receipt.

## Upgrade

Upgrade both the Server and selected Agents to 0.8.0 before relying on this
option. The Agent catalog response now includes
`skipClaudeModelsForOtherClients`. Older Agents reject the new response field
and may retain an earlier cached catalog rather than apply the new policy.
Updated Agents default to skipping Claude models for other clients when reading
older catalogs or cache files without the field.

Preserve existing Agent state, credentials, and model-selection records.
No re-enrollment or database migration is required. Native restoration and
unrelated client settings remain unchanged.

See the [CLIProxyAPI operations guide](../technical-design/cliproxy-operations.md).

## Verification

Local verification of the checkbox change passed 117 Server tests and 73 Rust
tests, formatting, Clippy, JavaScript syntax, and documentation-link checks.
Regression coverage includes policy defaults, legacy saved policies,
persistence, catalog delivery, client-specific pinned models, cached policy
handling, and native restoration.

The dashboard checkbox was exercised with mocked API responses for its default
checked state, saving it unchecked, reloading, and resetting changes. Live
Claude inference has not been tested.
