# Fleet Manager 0.3.0

This release adds the browser dashboard, enrollment links, and background Agent
services. Existing enrolled Nodes keep their identities and state.

## Server upgrade

The amd64 image is `skorcius/fleet-manager:0.3.0`. The dashboard is included in
that image; it does not need a separate container.

Back up PostgreSQL and your private configuration. Replace `compose.yaml` with
the copy from this release, keeping `.env`, `secrets/`, `operator.env`, `ssh/`,
and Docker volumes. Set `FLEET_IMAGE=skorcius/fleet-manager:0.3.0` in `.env`.

```sh
docker compose pull
docker compose up -d --force-recreate --wait
```

The migration service applies the new enrollment authorization columns before
the server starts. Do not rerun setup or delete volumes for an upgrade.

Open `https://YOUR_HOST:YOUR_PORT/dashboard` and sign in with your existing
Operator token. The browser must trust your server's CA. Compose supplies the
dashboard origin from `FLEET_HOSTNAME` and `FLEET_PORT`; `FLEET_PUBLIC_URL` can
override it. These settings do not regenerate certificates or change DNS.

## Homebrew installation

This repository also acts as the tap. The release workflow updates its formulas
after all client archives have been published.

```sh
brew tap jcarcaboso/fleet https://github.com/jcarcaboso/fleet-manager
brew install jcarcaboso/fleet/fleet-agent
brew install jcarcaboso/fleet/fleet
```

Prebuilt clients are available for Linux amd64, macOS Apple silicon, and macOS
Intel. Homebrew verifies the selected archive against its SHA-256 checksum.

Generate an alias-bound enrollment link in the dashboard, then on the Node:

```sh
fleet-agent enroll --link
brew services start jcarcaboso/fleet/fleet-agent
```

Paste the link at the prompt. It includes the public CA, so no separate CA or
enrollment JSON file needs transferring. The private key stays on the Node.
The link defaults to a 15-minute lifetime and can be revoked in the dashboard.

An already enrolled Node only needs the new binary and service setup. Keep its
Agent state. Stop the old foreground process or uninstall its old Agent-managed
service before enabling the Homebrew service. Do not run both simultaneously.

To update a Homebrew-managed Node:

```sh
brew services stop jcarcaboso/fleet/fleet-agent
brew update
brew upgrade jcarcaboso/fleet/fleet-agent
brew services start jcarcaboso/fleet/fleet-agent
```

Homebrew service definitions use the stable `opt` path. macOS starts the user
service at login. Linux uses the systemd user manager; boot before login needs
lingering enabled for that user. Install and run the Agent as the user whose
home contains the Skills.

## Validation and limits

Server and Agent regression tests cover enrollment, revocation, TLS validation,
state recovery, and service definitions. A real Agent was enrolled and polled
against the Docker image under the homelab Compose configuration.

macOS release binaries are built and tested on native GitHub runners. Actual
login-startup behavior still needs validation on your Macs. The Mac binaries
are not signed or notarized. Agent self-update is not implemented; upgrade one
Node and verify its contact and sync before updating the rest.
