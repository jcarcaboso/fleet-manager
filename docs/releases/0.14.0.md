# Fleet Manager 0.14.0

Images: `skorcius/fleet-manager:0.14.0` for the Server and
`skorcius/fleet-manager:dashboard-0.14.0` for the dashboard, Linux amd64.

This release adds the `fleet/v3` source manifest, fixes the CLIProxy model
catalog on a fresh installation, and reorganizes the Server and Rust clients
into modules without dependency cycles.

## fleet/v3 manifest

`fleet/v3` declares `skills`, `agents` and `ai-clients` once under the top-level
`targets` and applies them to every Node listed under `nodes`. A Node's own
`targets` override the defaults:

- `skills`: each field the Node sets replaces the default field.
- `agents`: setting the key replaces the whole default list.
- `ai-clients`: entries merge by client name. `<client>: ~` drops one default
  client and `ai-clients: ~` drops all of them.

The top-level `targets.skills` must set `base: home` and a valid `path`. Each
Node's resolved Targets are validated and published as if they had been written
out in `fleet/v2`, so Agents see no difference. A Node missing from `nodes`
still receives nothing. See
[Fleet-wide defaults](../architecture/desired-state.md#fleet-wide-defaults-in-fleetv3)
and [`examples/source/fleet-defaults.yml`](../../examples/source/fleet-defaults.yml).

`fleet/v1` and `fleet/v2` manifests keep working unchanged.

## CLIProxy catalog before the first Node

The Server only synced the model catalog of base URLs used by current CLIProxy
Assignments. A fresh installation with `cliproxy.base-url` in `fleet.yml` and no
enrolled Node listed no models and offered no model selection. The source scan
now carries the manifest's normalized `cliproxy.base-url`, and the catalog sync
includes it before any Node is assigned.

## Internal changes

The Server's coordinator is split into six role interfaces, and error types,
CLIProxy, the Agent release mirror, metrics and source polling have their own
folders. `ModuleBoundaryTests` keeps the namespaces free of cycles. In the
Rust clients, the Agent's `main.rs` and `fleet-reconcile` are split into
smaller modules, and wire types live in `protocol/wire.rs`. This work intends no
behavior change. Logger categories follow the classes that moved folders, so a
log filter that names an old category must be updated.

`quinn-udp` is updated to 0.5.16 for RUSTSEC-2026-0538.

## Breaking changes

None for Operators or Agents. There is no database migration, and the Agent and
Operator API contracts are unchanged.

## Upgrade

1. Back up PostgreSQL and private configuration using the
   [backup guide](../technical-design/backup-restore.md). From a repository
   checkout with access to the installation's Docker daemon:

   ```sh
   python3 scripts/postgres-backup.py backup \
     --container <postgres-container> .local/backups/pre-0.14.0
   ```

2. Preserve `.env`, `secrets/`, `operator.env`, `ssh/`, Agent state, and Docker
   volumes. Upgrade the Server and dashboard together, before updating Agents:

   ```sh
   # Set these image references in the existing deployment's .env:
   # FLEET_IMAGE=skorcius/fleet-manager:0.14.0
   # FLEET_DASHBOARD_IMAGE=skorcius/fleet-manager:dashboard-0.14.0
   docker compose pull
   docker compose up -d --force-recreate --wait
   ```

3. Upgrade the Server before committing a `fleet/v3` manifest to the source
   repository. A Server older than 0.14.0 does not know the schema and cannot
   accept that manifest.
4. The Agent protocol is unchanged, so Agents of 0.13.0 are expected to keep
   working with this Server; this was not tested against a previous-release
   Agent. After the signed release archives are published, update Agents
   through the dashboard or `fleet nodes update`.
5. No CA renewal, reenrollment, or service-definition change is required. The
   Server image can be rolled back to 0.13.0 as long as no `fleet/v3` manifest
   is in the source repository.

## Verification

- Source scanner tests cover `fleet/v3` defaults, per-Node overrides, explicit
  nulls and invalid defaults. Hosting tests cover the catalog sync of the
  manifest's base URL.
- Release signing keys are unchanged from 0.13.0.
- Not yet verified for this release: the full `CONTRIBUTING.md` checks on the
  version bump commit, image smoke tests, published archive provenance, the
  manifest signature, Homebrew formulas, and a disposable-stack self-update.
  These are checked during publication, and any unfinished check is reported
  with the release.
