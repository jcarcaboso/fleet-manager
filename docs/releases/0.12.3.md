# Fleet Manager 0.12.3

Images: `skorcius/fleet-manager:0.12.3` for the Server and
`skorcius/fleet-manager:dashboard-0.12.3` for the dashboard, Linux amd64.

This release fixes Claude Skills delivery for Nodes that do not configure agent
instruction files or a Claude connection. It also adds an explicit exclusion
that removes Fleet-managed Claude Skills. There is no database migration or
dependency update.

## Claude Skills

Every Node now receives its resolved Skills at
`~/.claude/skills/<skill-name>/SKILL.md`, independently of `targets.agents` and
`targets.ai-clients`. Previously, the Server only published that destination
when one of those settings selected Claude.

Both `fleet/v1` and `fleet/v2` accept `excludeClaude` under `targets.skills`.
It defaults to `false`. Set a Workspace default or override it for a Node:

```yaml
targets:
  skills:
    base: home
    path: .agents/skills
    excludeClaude: false

nodes:
  example-node:
    targets:
      skills:
        groups: []
        excludeClaude: true
```

Exclusion publishes an empty Claude Skills map. On reconciliation, the Agent
removes Skills recorded in its ownership receipt while preserving personal
Skills and other unowned content, including existing `synced/` directories.
Setting the flag back to `false` installs the Node's resolved Skills again.

The configured shared Skills destination is unchanged unless it already points
at `.claude/skills`. In that case, Fleet uses that Target without a duplicate,
and exclusion empties its desired Skills map.

Removing a Skill from an accepted source revision or a Node's resolved selection
also removes its installed copy from each managed destination. Removing the last
Skill or the optional `skills/` source root works when no missing groups are
explicitly selected. Invalid revisions leave the previous desired state active.

## Upgrade

1. Back up PostgreSQL and private configuration using the
   [backup guide](../technical-design/backup-restore.md).
2. Upgrade the Server and dashboard together. Set
   `FLEET_IMAGE=skorcius/fleet-manager:0.12.3` and
   `FLEET_DASHBOARD_IMAGE=skorcius/fleet-manager:dashboard-0.12.3` in `.env`, then
   run `docker compose pull` and `docker compose up -d --force-recreate --wait`.
3. Agents on 0.12.2 already support the Claude Skills Target and owned-Skill
   removal. Older Agents keep receiving their existing Targets, but Claude
   delivery and cleanup remain pending until they announce `claude-skills`.
   Update them from the dashboard or with `fleet nodes update` after the
   release archives are published.
4. Commit and push a new source revision, then run `fleet source rescan`.
   Previously accepted revisions are immutable; rescanning the same accepted
   commit does not rebuild its Assignments. Use `excludeClaude: true` before
   publishing for Nodes that should not receive Fleet-managed Claude Skills.

This patch does not require another CA renewal or a change to enrollment,
ownership receipts, or service definitions.

## Verification

- Server tests cover skills-only Nodes, both manifest versions, inherited
  defaults and Node overrides, exclusion cleanup, re-enabling, and repository
  removal through persisted Assignments.
- Agent tests cover direct destination paths, independent reconciliation,
  partial and complete owned-Skill removal, and preservation of unowned content.
- Cargo audit reports the existing Tokio 1.53.1 warning `RUSTSEC-2026-0386`
  concerning I/O safety in `AsyncFd` constructors. Locked dependencies are
  unchanged from 0.12.2.
- CI must pass on the PR before merge and on the release commit before tagging.
  macOS behavior is not verified locally.
- Image publication, release tagging, signed archives, Homebrew updates, and
  verification of published artifacts happen after the release PR is merged.
